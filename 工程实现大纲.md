### ZeroVector Java 25 工程实现大纲
#### 1. 技术栈与核心设计
*   **语言与运行时**：JDK 25 (利用 **Records**, **Pattern Matching for switch**, **Virtual Threads**, **String Templates**)。
*   **LLM 集成**：**LangChain4j**（Java 领域最成熟的 LLM 编排框架）。
*   **序列化**：Jackson (JSON) + 自定义二进制格式 (索引)。
*   **高性能 I/O**：`java.nio.channels.FileChannel` + `MappedByteBuffer` (mmap)。
*   **构建工具**：Maven 3.9+。
#### 2. 核心架构分层

#### 3. 详细模块设计
##### 模块一：领域模型
利用 Java Records 实现不可变数据载体，使用 Sealed Interfaces 定义行为。
*   `NodeType` (Enum): `ROOT`, `CATEGORY`, `LEAF`.
*   `TreeNode` (Record): id, name, description, type, childrenIds, chunkIds.
*   `DocumentChunk` (Record): id, content, summary, metadata.
*   `NavigationAction` (Sealed Interface): 定义导航行为（`SelectChild`, `ExpandMultiple`, `SelectLeaves`）。
    **Java 25 特性应用**：
*   使用 **Record Patterns** 在导航逻辑中解构 `TreeNode`。
*   使用 **Switch Expressions with Patterns** 简化 Action 处理逻辑。
##### 模块二：高性能存储引擎 (Storage Engine with mmap)
这是本方案的核心亮点。传统方式是将所有文档加载到堆内存，会导致巨大的 GC 压力。mmap 方案利用操作系统虚拟内存管理，按需加载。
*   **`MMapDocumentStore`**:
    *   负责将大文件（如 `documents.data`）映射到内存。
    *   文件格式：`[ChunkLength(4字节)][ChunkContent(变长)]...`
    *   维护一个内存中的索引：`Map<String, FileLocation>`，其中 `FileLocation` 包含 `offset` 和 `length`。
    *   **读取流程**：根据 Chunk ID 从索引拿到 Offset -> 直接从 MappedByteBuffer 读取对应字节区域。零拷贝，极快。
##### 模块三：LLM 服务集成
*   **`LLMService`**:
    *   封装 LangChain4j 的 `ChatLanguageModel`。
    *   提供 `completeJson(String prompt, Class clazz)` 方法，支持结构化输出（直接映射为 Java Record）。
    *   配置支持流式输出（用于调试）。
##### 模块四：语义树构建器
*   **`TreeBuilder`**:
    *   **并发处理**：利用 **Virtual Threads (`Executors.newVirtualThreadPerTaskExecutor()`)** 对大规模文档进行并发摘要生成或初步分析。
    *   **递归逻辑**：读取文档摘要 -> 调用 LLM 聚类 -> 创建节点 -> 递归处理子节点。
    *   **持久化**：将构建好的 `SemanticTree` 序列化为 JSON 存盘，同时将文档内容写入 mmap 文件并生成索引。
##### 模块五：语义导航器
*   **`Navigator`**:
    *   **状态机模式**：维护当前节点状态。
    *   **路径追踪**：记录 `NavigationPath` (query, visitedNodes, reasoning)。
    *   **决策逻辑**：
        1. 加载当前节点的子节点信息。
        2. 携带用户问题请求 LLM。
        3. 解析 LLM 返回的 `NavigationAction`。
        4. 根据 Action 跳转或读取文档。

### 关键代码骨架
#### 1. MMap 存储核心实现
```java
import java.io.IOException;
import java.io.RandomAccessFile;
import java.lang.foreign.Arena; // Java 22+ FFM API (若 JDK 25 可用)
import java.nio.MappedByteBuffer;
import java.nio.channels.FileChannel;
import java.nio.charset.StandardCharsets;
import java.util.HashMap;
import java.util.Map;
public final class MMapDocumentStore {
    private final MappedByteBuffer buffer;
    // 索引：ChunkID -> (文件偏移量, 长度)
    private final Map<String, FileLocation> index = new HashMap<>();
    public record FileLocation(long offset, int length) {}
    public MMapDocumentStore(String filePath, long fileSize) throws IOException {
        try (RandomAccessFile file = new RandomAccessFile(filePath, "r");
             FileChannel channel = file.getChannel()) {
            // 将文件映射到内存
            this.buffer = channel.map(FileChannel.MapMode.READ_ONLY, 0, fileSize);
            // 加载索引（假设索引是单独存储的，这里简化逻辑）
            loadIndex(); 
        }
    }
    public String getChunk(String chunkId) {
        FileLocation loc = index.get(chunkId);
        if (loc == null) return null;
        
        // 从 mmap buffer 中直接读取，无需系统调用 read()
        byte[] bytes = new byte[loc.length()];
        // 注意：需要处理 buffer position 的线程安全问题，或使用 slice()
        // 此处简化演示
        int originalPosition = buffer.position();
        buffer.position((int) loc.offset());
        buffer.get(bytes);
        buffer.position(originalPosition); // 还原位置
        
        return new String(bytes, StandardCharsets.UTF_8);
    }
    
    // ... index loading logic
}
```
#### 2. 领域模型与模式匹配

```java
// 导航动作的 Sealed Interface
public sealed interface NavigationAction permits SelectChild, SelectLeaves, Stop {
    record SelectChild(String nodeId, String reasoning, double confidence) implements NavigationAction {}
    record SelectLeaves(List<String> chunkIds, String reasoning) implements NavigationAction {}
    record Stop(String reasoning) implements NavigationAction {}
}
// 导航逻辑中的模式匹配
public void processAction(NavigationAction action) {
    switch (action) {
        case SelectChild(String nodeId, String reasoning, double confidence) -> 
            navigateTo(nodeId);
            
        case SelectLeaves(List<String> chunkIds, String reasoning) -> 
            loadDocuments(chunkIds);
            
        case Stop(String reasoning) -> 
            endNavigation();
    }
}
```

### 实施步骤建议
1.  **Project Setup**: 创建 Maven 项目，引入 `langchain4j-openai`, `jackson-databind`。
2.  **Storage First**: 先实现 `MMapDocumentStore`，编写单元测试验证亿级字节文件的随机读取性能。
3.  **Domain & LLM**: 定义 Records，封装 `LLMService`，跑通简单的 JSON 提示和解析。
4.  **Builder**: 实现单层聚类逻辑，测试 LLM 输出的解析稳定性。
5.  **Navigator**: 实现基于 `NavigationAction` 的路由逻辑。
6.  **Integration**: 端到端测试：Markdown 文件 -> MMap 存储 -> 建树 -> 查询。
    这个方案将 ZeroVector 从一个 Python 原型转变为一个**高性能、原生**的 Java 知识库引擎，能够利用 mmap 处理远超内存限制的数据量，同时保持极低的 GC 开销。
