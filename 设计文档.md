# ZeroVector 系统架构设计文档 (Java 25 实现)
**项目代号**：ZeroVector  
**核心目标**：构建一个**不依赖向量数据库**，基于**语义决策树导航 (SDTN)** 与 **关键词倒排索引** 的混合智能知识库系统。  
**技术栈**：Java 25 (Records, Virtual Threads, Pattern Matching), Memory Mapped Files (mmap)。
---
## 一、 系统核心架构
系统采用分层架构，核心数据流向为：`查询 -> 关键词定位/语义导航 -> mmap文件读取 -> 结果生成`。
```mermaid
graph TD
    subgraph "Offline Building (Indexing)"
        A[原始文档] --> B[TreeBuilder]
        B --> C{LLM 聚类与提取}
        C --> D[Semantic Tree (JSON)]
        C --> E[Keyword Dictionary (倒排索引)]
        C --> F[Raw Content Store (mmap二进制文件)]
    end
    subgraph "Online Querying"
        G[用户查询] --> H[HybridNavigator]
        H --> I{关键词词典匹配?}
        I -- 命中 --> J[快速跳转]
        I -- 未命中 --> K[语义推理导航]
        J --> L[LLM 决策确认]
        K --> L
        L --> M[叶子节点]
        M --> N[Storage Engine]
        N --> O[MMapDocumentStore]
        O --> P[读取文档内容]
    end
```

## 二、 核心模块详细设计
### 1. 存储引擎 - `core.storage`
**目标**：利用 mmap 实现海量文档内容的零拷贝读取，避免 JVM 堆内存溢出。
#### 1.1 文件格式设计
使用两个核心文件：
*   `content.data`：二进制数据文件。格式：`[Length(4字节)][Content(变长字节)]...`
*   `content.index`：内存加载的索引文件。格式：`Map<ChunkId, (Offset, Length)>`
#### 1.2 核心代码实现
```java
package com.zerovector.storage;
import java.io.IOException;
import java.io.RandomAccessFile;
import java.nio.MappedByteBuffer;
import java.nio.channels.FileChannel;
import java.nio.charset.StandardCharsets;
import java.util.HashMap;
import java.util.Map;
/**
 * 基于 mmap 的高性能文档存储
 * [CRITICAL] 必须保证线程安全，读取时使用 buffer.slice() 防止 position 指针冲突
 */
public final class MMapDocumentStore {
    
    private final MappedByteBuffer buffer;
    // 索引：ChunkID -> (文件偏移量, 长度)
    // [OPTIMIZATION] 使用 Java 25 的 StableValue 或 immutable map 保证读安全
    private final Map<String, FileLocation> index = new HashMap<>();
    public record FileLocation(long offset, int length) {}
    public MMapDocumentStore(String filePath) throws IOException {
        try (RandomAccessFile file = new RandomAccessFile(filePath, "r");
             FileChannel channel = file.getChannel()) {
            // 映射整个文件到虚拟内存
            this.buffer = channel.map(FileChannel.MapMode.READ_ONLY, 0, channel.size());
        }
        loadIndex(); // 加载索引
    }
    /**
     * 根据ID读取文档内容
     * [KEY] 零拷贝读取，极快
     */
    public String getChunk(String chunkId) {
        FileLocation loc = index.get(chunkId);
        if (loc == null) return null;
        // [CRITICAL] 使用 slice 创建独立视图，避免多线程竞争 buffer position
        synchronized (this) { // 或者使用 Off-Heap Region 进一步优化
            buffer.position((int) loc.offset());
            byte[] bytes = new byte[loc.length()];
            buffer.get(bytes);
            return new String(bytes, StandardCharsets.UTF_8);
        }
    }
    
    private void loadIndex() { /* 实现索引加载逻辑 */ }
}
```

### 3. 混合索引与词典 - `index`
**目标**：解决“LLM 不认识专有名词”的问题，提供关键词快速跳转能力。
#### 3.1 关键词词典结构
```java
package com.zerovector.index;
import java.util.*;
import java.util.concurrent.ConcurrentHashMap;
/**
 * 关键词倒排索引
 * [CRITICAL] 必须支持高并发读取
 */
public final class KeywordDictionary {
    
    // 倒排索引：Keyword -> List<NodeId>
    private final Map<String, List<String>> invertedIndex = new ConcurrentHashMap<>();
    
    // 权重索引：Keyword -> Weight (用于排序)
    private final Map<String, Double> keywordWeights = new ConcurrentHashMap<>();
    /**
     * 匹配查询中的关键词，返回候选节点
     * [KEY] 混合检索的第一步
     */
    public Map<String, Double> matchCandidates(String query) {
        Map<String, Double> candidateScores = new HashMap<>();
        
        // 简单分词匹配 (可升级为 AC 自动机或 FST)
        Arrays.stream(query.split("\\s+"))
            .filter(invertedIndex::containsKey)
            .forEach(kw -> {
                double weight = keywordWeights.getOrDefault(kw, 1.0);
                invertedIndex.get(kw).forEach(nodeId -> 
                    candidateScores.merge(nodeId, weight, Double::sum)
                );
            });
            
        return candidateScores;
    }
}
```

        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            var futures = chunks.stream()
                .map(c -> executor.submit(() -> summarizeAndExtract(c)))

        // 持久化树和词典
        saveTree(root);
        saveDictionary(dictionary);
        return new SemanticTree(root);
    }
    private TreeNode buildRecursive(String name, List<DocumentChunk> chunks) {
        // 1. 调用 LLM 进行聚类

            // 递归处理子节点
            buildRecursive(cat.getName(), cat.getChunks());
        }
        // ...
    }

### 5. 混合导航器 - `navigator`
**目标**：结合关键词跳转与 LLM 语义推理，实现精准导航。
#### 5.1 核心导航逻辑
```java
package com.zerovector.navigator;
public class HybridNavigator {
    
    private final SemanticTree tree;
    private final KeywordDictionary dictionary;
    private final LLMService llm;
    private final MMapDocumentStore store;
    public NavigationPath navigate(String query) {
        // [Phase 1] 关键词匹配 (快速通道)
        Map<String, Double> candidates = dictionary.matchCandidates(query);
        String fastTrackNodeId = null;
        
        // 如果存在高权重命中，走快速通道
        if (!candidates.isEmpty()) {
            fastTrackNodeId = Collections.max(candidates.entrySet(), Map.Entry.comparingByValue()).getKey();
        }
        // [Phase 2] LLM 语义决策
        TreeNode currentNode = (fastTrackNodeId != null) 
            ? tree.getNode(fastTrackNodeId) 
            : tree.getRoot();
        return navigateInternal(query, currentNode);
    }
    private NavigationPath navigateInternal(String query, TreeNode startNode) {
        List<TreeNode> path = new ArrayList<>();
        path.add(startNode);
        TreeNode current = startNode;
        while (current.type() != NodeType.LEAF) {
            // 构建带"提示"的 Prompt
            String prompt = buildNavigationPrompt(query, current);
            
            // 调用 LLM
            NavigationAction action = llm.decide(prompt);
            
            // [KEY] 模式匹配处理决策
            switch (action) {
                case SelectChild(String nodeId, String reasoning, double conf) -> {
                    // 如果置信度过低，触发 Fallback
                    if (conf < 0.3) {
                        return handleFallback(query);
                    }
                    current = tree.getNode(nodeId);
                    path.add(current);
                }
                case ExpandMultiple(List<String> nodeIds, String reasoning) -> {
                    // [Phase 1 功能] 多分支并行处理
                    return handleMultiPath(query, nodeIds);
                }
                case FallbackSearch(String reason) -> {
                    return handleFallback(query);
                }
                default -> { /* Stop or others */ }
            }
        }
        
        // [Phase 3] 到达叶子节点，读取文档
        return new NavigationPath(query, path, loadChunks(current.chunkIds()));
    }
    /**
     * [CRITICAL] 构建 Prompt 时注入关键词信息
     */
    private String buildNavigationPrompt(String query, TreeNode node) {
        // 获取当前节点的关键词，显式告诉 LLM
        String keywordHints = String.join(", ", node.keywords());
        
        return """
            用户问题: %s
            当前节点: %s
            该节点核心实体: %s
            
            请判断应该进入哪个子节点？
            """.formatted(query, node.name(), keywordHints);
    }
}
```

## 三、 LLM Prompt 设计规范
所有 LLM 调用均要求结构化输出 (JSON)。
### 1. 聚类 Prompt (离线)
```text
任务：将以下文档摘要归纳为 3-5 个语义分类。
要求：
1. 为每个分类提供 name 和 description。
2. 提取每个分类的 keyEntities（如项目名、人名）。
3. 输出 JSON 格式。
文档列表：...
```
### 2. 导航 Prompt (在线)
```text
任务：根据用户问题，在语义树中选择下一步动作。
当前节点信息：
- 名称：技术文档
- 描述：包含架构设计、代码实现
- 核心实体：Java, Redis, Service-A (关键点：注入词典信息)
用户问题：Service-A 的连接池怎么配置？
可选动作：
1. SELECT_CHILD: 选择一个子节点
2. STOP: 停止
输出 JSON 格式：
{"action": "SELECT_CHILD", "nodeId": "...", "confidence": 0.9}
```

## 四、 关键实施检查点
1.  **内存安全**：mmap 读取必须使用 `buffer.slice()` 或 `synchronized`，防止多线程并发读取导致 Buffer 指针错乱。
2.  **词典构建**：必须在 `TreeBuilder` 离线阶段完成，在线运行时词典只读。
3.  **Fallback 机制**：当 LLM 返回 `confidence < 0.3` 时，必须切换到关键词全文搜索或倒排索引检索，确保系统可用性底线。
4.  **并发控制**：`TreeBuilder` 使用 `Executors.newVirtualThreadPerTaskExecutor()`，充分利用 Java 25 的轻量级线程。
